# 🛡️ AI Security Workflow — Визуальная платформа автоматизации проверок безопасности

Разработано для хакатона **Cyber Garden 2026** (Кейс от **Банка «Центр-инвест»**).

**AI Security Workflow** — это специализированная no-code / low-code веб-платформа (DAG Workflow Builder), позволяющая командам разработчиков визуально конструировать сценарии аудита безопасности кода, находить секреты, уязвимые зависимости (SCA) и архитектурные дефекты (SAST) в приложениях на **Kotlin / Spring Boot / Gradle KTS**, получать понятные AI-рекомендации по устранению рисков и автоматически блокировать уязвимые коммиты в CI/CD.

## ✨ Ключевые возможности и реализация требований

### 1. Визуальный редактор и движок выполнения (DAG Engine)
- **Собственный движок исполнения**: Топологическая сортировка Кана, параллельное выполнение независимых веток, поддержка условных развилок (If/Else) с отсечением неактивных веток.
- **Живая визуализация (Live SSE Stream)**: Реал-тайм подсветка статусов блоков (`running`, `completed`, `failed`), анимированные бегущие импульсы по связям и бейджи количества находок.
- **Инспектор данных (Data Inspector в стиле n8n)**: Просмотр входных (Inputs) и выходных (Outputs) JSON-данных для каждого блока на холсте.
- **Single Node Run**: Кнопка *«Протестировать этот блок»* для изолированного запуска отдельной ноды без прогона всего сценария.

### 2. Собственные анализаторы безопасности (Без готовых сканеров)
- **SECRET Scanner**:
  - Детектирование захардкоженных паролей, API-ключей, токенов.
  - Расчёт энтропии Шеннона ($H > 3.3$).
  - Отслеживание конкатенации строк и Kotlin Elvis-операторов (`?: fallback`).
  - Парсинг `application.yml` с поддержкой безопасных ссылок `${ENV_VAR}`.
  - Маскирование всех чувствительных значений в логах и UI.
- **SCA Scanner**:
  - Разбор `build.gradle.kts`, `gradle.properties` и `gradle.lockfile`.
  - Строгое числовое сравнение версий слева направо (`1.9 == 1.9.0`, `20230227`).
  - Сопоставление диапазонов уязвимостей с базой `vulnerabilities.json`.
- **SAST Scanner (Kotlin / Spring Boot)**:
  - `sql-injection`: Выявление непараметризованных SQL-запросов с интерполяцией `$var` (в отличие от безопасных с `?`).
  - `tls-verification`: Выявление отключения проверки сертификатов хоста (`HostnameVerifier { _, _ -> true }`).
  - `credentialed-cors`: Выявление опасной связки `allowedOriginPatterns = ["*"]` и `allowCredentials = true`.
  - `route-authorization`: Выявление ошибочно открытых конфиденциальных эндпоинтов (`permitAll()`).
  - `object-authorization`: Детект IDOR / BOLA без сверки с `principal.name` или `customerId`.

### 3. Обязательный двойной отчёт (Dual Report)
Каждый запуск генерирует:
1. **`submission-report.json`**: Машиночитаемый JSON в кодировке UTF-8 строго по спецификации `submission-format.md`:
   - Относительные пути `path`.
   - Целочисленные номера строк `line` и `endLine` для `SECRET` и `SAST`.
   - Точные координаты `group`, `artifact`, `version`, `advisoryId` для `SCA`.
   - Замаскированные значения секретов.
2. **Читаемый отчёт**: Интерактивная таблица в интерфейсе и Markdown-файл `audit-report.md` с AI-рекомендациями по устранению.

### 4. Задачи со звёздочкой (★)

#### ★ 1. Библиотека готовых шаблонов сценариев
- Каталог готовых пресетов в UI:
  1. *«Комплексный аудит безопасности (Full DAG)»*
  2. *«Быстрый аудит утечек секретов»*
  3. *«SCA & Мониторинг зависимостей Gradle»*
  4. *«CI/CD Gatekeeper: Блокировка сборки»*
- Применение любого шаблона на холст в 1 клик.
- Возможность публикации пользовательских сценариев через API (`POST /api/templates/publish`).

#### ★ 2. Интеграция в CI/CD Пайплайн (GitHub Actions & GitLab CI)
- Генератор готовых конфигурационных файлов (`.github/workflows/security.yml`, `.gitlab-ci.yml`) в модальном окне UI.
- Эндпоинт Headless-запуска: `POST /api/ci/run`.
- **Fail-on-Critical**: Автоматический возврат `exitCode: 1` при наличии критических или высоких уязвимостей, ломающий сборку и формирующий Markdown-отчёт для комментария в Pull Request.

#### ★ 3. AI-генерация сценария по тексту (Text-to-Workflow / NL2Graph)
- Ввод задачи на естественном языке (например, *«Каждый день в 14:00 проверяй репозиторий на секреты и зависимости и шли в телеграм»*).
- Автоматический подбор триггеров, сканеров, агрегаторов, логики условий и каналов связи с мгновенной отрисовкой на холсте.

### 5. Архитектурные преимущества
- **Полноценная база данных PostgreSQL**: Все запуски (`workflow_runs`), индивидуальные находки (`findings`), шаблоны (`workflow_templates`), двойные отчёты (`reports`), справочник уязвимостей (`vulnerabilities`) и секреты хранятся в реляционной БД с индексами и внешними ключами.
- **Отказоустойчивость (Resilient Fallback)**: При временной недоступности PostgreSQL платформа автоматически переходит в режим in-memory с сохранением полной работоспособности и автоподключением при восстановлении БД.
- **Модульный реестр нод (`NodeRegistry`)**: Добавление новой ноды требует создания лишь одного объекта с метаданными и функцией `run`. Включена специализированная нода `storage.postgres`.
- **Шифрование секретов (Vault)**: Все пользовательские токены и пароли шифруются алгоритмом `AES-256-GCM` и маскируются в логах.
- **Поддержка локальных LLM**: Переключение между бесплатным Cloud API и локальным Ollama (`localhost:11434/v1`) без изменения бизнес-логики.
- **Hallucination Guard**: Строгая валидация AI-ответов по реальным номерам строк и CVE для исключения галлюцинаций.

## 📁 Структура проекта

```
.
├── backend/
│   ├── src/
│   │   ├── analyzers/
│   │   │   ├── secrets/       # Анализатор секретов, энтропия, Elvis, конкатенация
│   │   │   ├── sca/           # Анализатор зависимостей Gradle KTS и справочник CVE
│   │   │   └── sast/          # SAST-анализатор Kotlin/Spring Boot (SQLi, TLS, CORS, IDOR)
│   │   ├── engine/            # DAG движок выполнения графа, топология, события
│   │   ├── nodes/             # Модульный реестр нод (Triggers, Scanners, Logic, AI, Storage, Reports)
│   │   ├── templates/         # Каталог готовых шаблонов сценариев (★)
│   │   ├── cicd/              # CI/CD генератор и runner с fail-on-critical (★)
│   │   ├── ai/                # Text-to-Workflow генератор и AI-эксплейнер (★)
│   │   ├── storage/           # PostgreSQL DB сервис (pg.Pool), DDL schema.sql, Vault AES-256-GCM
│   │   └── server.ts          # REST API + Live SSE Server
│   ├── public/
│   │   └── index.html         # Современный Web UI (Canvas, Data Inspector, Modals)
│   └── test/
│       ├── ground-truth.test.ts   # Тест точности на учебном эталоне (15/15 + 6 controls)
│       ├── workflow-engine.test.ts # Тест сквозного DAG-исполнения
│       └── postgres-storage.test.ts # Тест PostgreSQL хранилища, схемы и CRUD
├── docker/
│   └── init.sql               # Скрипт инициализации БД PostgreSQL для Docker
├── test-dataset/              # Учебный датасет (training-project, ground-truth, vulnerability-db)
├── reports/                   # Каталог сгенерированных отчётов (submission-report.json)
├── Dockerfile                 # Multi-stage production container
├── docker-compose.yml         # Развертывание в 1 команду (PostgreSQL 16 + Backend)
└── package.json
```

## 📜 Спецификация API

| Метод | Эндпоинт | Описание |
| :--- | :--- | :--- |
| `GET` | `/` | Веб-интерфейс конструктора сценариев |
| `GET` | `/api/events` | Server-Sent Events (SSE) поток живых статусов |
| `GET` | `/api/nodes` | Список всех доступных блоков и схем параметров |
| `POST` | `/api/workflow/run` | Запуск DAG-сценария аудита с сохранением в PostgreSQL |
| `POST` | `/api/workflow/run-node`| Изолированный запуск отдельного блока (Single Run) |
| `GET` | `/api/templates` | Список готовых шаблонов сценариев из PostgreSQL (★) |
| `POST` | `/api/templates/publish` | Сохранение сценария в библиотеку шаблонов в PostgreSQL (★) |
| `DELETE` | `/api/templates/:id` | Удаление пользовательского сценария из PostgreSQL (★) |
| `POST` | `/api/ai/generate-workflow` | Генерация сценария по тексту на естественном языке (★) |
| `GET` | `/api/ci/config` | Генерация конфигурации GitHub Actions / GitLab CI (★) |
| `POST` | `/api/ci/run` | CI/CD Headless runner с падением при уязвимостях (★) |
| `GET` | `/api/reports/latest` | Получение последнего двойного отчёта из PostgreSQL (JSON + Markdown) |
| `GET` | `/api/history` | История запусков аудита из таблицы `workflow_runs` |
| `GET` | `/api/history/:id` | Детали конкретного запуска и список находок по ID |
| `GET` | `/api/findings` | Поиск и фильтрация находок (`runId`, `category`, `severity`, `search`) |
| `GET` | `/api/findings/stats` | Агрегированная статистика находок по критичности и категориям |
| `GET` | `/api/db/health` | Диагностика подключения и статус таблиц PostgreSQL |
